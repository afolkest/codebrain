# codebrain — Canonical schema (the locked envelope)

The normalized layer every adapter emits into. Downstream (FTS, vectors, files index, CLI) reads **only** this and stays format-blind.

This is a **rebuildable cache** (see DESIGN.md): raw evidence in the sync pool is
the source of truth; anything here can be dropped and regenerated by re-running
adapters. For Cursor, raw evidence means codebrain's safe immutable projection,
not the live application database. "Locked" means the table shapes and rules
below are the fixed contract — not that they can never change (change = re-ingest
from raw evidence).

Source-format mechanics live in `formats/{claude,codex,cursor,pi}.md`. This doc
references them rather than repeating them.

## Core model: content vs placement

The decisive design fact: **an event's content is shared, but its position in a transcript is per-session.** pi's resume/branch copies a parent's records *verbatim* into a new file, so the same logical event can appear in several sessions — and can be **live in one and rolled-back-dead in another**. Therefore liveness and order cannot be properties of the event; they're properties of an (event, session) pairing.

So three tables:

- **`events`** — immutable, deduped **content** ("what was said"). One row per logical event.
- **`session_events`** — **placement** ("this event appears in this session's transcript here, alive/dead, inherited or authored"). The forest lives here (`parent_event_id`).
- **`sessions`** — session metadata + lineage/sub-agent links + the tip.

Every placement carries `parent_event_id` → events form a **forest**; a session is
a named tip into it. This is native for Claude (`parentUuid`) and pi (`parentId`),
and synthesized from structured order for Codex and Cursor. FTS5, sqlite-vec, and
a files index are derived layers, out of scope here.

## `events` — content (deduped)

| column | type | semantics |
|---|---|---|
| `event_id` | TEXT PK | Adapter-minted, deterministic, globally unique, **copy-invariant**. `<source>:…` (see ID scheme). Upsert key. |
| `origin_session_id` | TEXT NULL | The session that *authored* this event (the one `session_events` row with `inherited=0`). NULL until that session is ingested (a copy may arrive first — eventual consistency). |
| `ts` | TEXT NOT NULL | ISO-8601 UTC. The original authoring time (copies preserve it). |
| `actor` | TEXT NOT NULL | `user` \| `assistant` \| `tool`. |
| `type` | TEXT NOT NULL | `message` \| `tool_call` \| `tool_result`. |
| `text` | TEXT NULL | Normalized, searchable text. **No reasoning** (see Exclusions). Full content; chunking is the index layer's job. |
| `refs` | JSON | `{ "files": [...], "commands": [...] }`. |
| `tool_call_event_id` | TEXT NULL | For a `tool_result` event: the `event_id` of its paired `tool_call`. Pairing is **intrinsic** (same in every placement, copy-invariant), kept **separate from** `parent_event_id` (transcript order) — for parallel calls the two differ. NULL otherwise. |
| `raw` | JSON NOT NULL | The adapter's canonical raw evidence. Usually the original `.jsonl` record; for Cursor, the allowlisted projected bubble payload. Multiple events may share one raw record (multi-block/tool-bearing records). Retains the safe source topology needed for forensics. |

## `session_events` — placement (the forest)

| column | type | semantics |
|---|---|---|
| `session_id` | TEXT NOT NULL | FK → `sessions`. |
| `event_id` | TEXT NOT NULL | FK → `events`. |
| `seq` | INTEGER NOT NULL | Order along this session's transcript, from the adapter's **linearization** (see below). Live branch is contiguous; off-branch events interleave by branch point. |
| `parent_event_id` | TEXT NULL | Normalized transcript predecessor **within this session** (NULL at a root). May reference an event owned by an ancestor session (pi/Cursor lineages). |
| `live` | INTEGER NOT NULL | `1` if on this session's live branch (ancestor of `sessions.tip_event_id`); else `0` (a rolled-back attempt). |
| `inherited` | INTEGER NOT NULL | `1` if copied from an earlier/ancestor session (pi/Cursor), even when its exact parent is unresolved; `0` if authored here. Exactly one session has `inherited=0` per event = its origin. |

PK `(session_id, event_id)`. Indexes: `(session_id, live, seq)`, `(event_id)`, `(parent_event_id)`.

Default read of a session's transcript:
```sql
SELECT e.* FROM session_events se JOIN events e USING(event_id)
WHERE se.session_id = ? AND se.live = 1 ORDER BY se.seq;
```
(A convenience VIEW `transcript` pre-joins these.) Forensics incl. rolled-back attempts: drop `live = 1`.

## `sessions`

| column | type | semantics |
|---|---|---|
| `session_id` | TEXT PK | `<source>:<sourceSessionId>` (UUID-like for most sources; Cursor uses `composerId`). |
| `source` | TEXT | `claude` \| `codex` \| `cursor` \| `pi`. |
| `machine` | TEXT | Hostname, from the pool path `raw/<hostname>/…` (logs don't carry it). |
| `cwd` | TEXT | From the session/meta record. |
| `repo` | TEXT NULL | Git root/remote, best-effort; may be NULL. |
| `created_at` | TEXT | The session record's own timestamp = **when this session began** (the resume moment for a child). **Threshold for the inherited/authored split.** |
| `started_at` | TEXT | Earliest event `ts` (may predate `created_at` for a child whose first events are inherited). |
| `ended_at` | TEXT | Latest event `ts`. |
| `parent_session_id` | TEXT NULL | Lineage/spawn parent. |
| `relation` | TEXT NULL | `NULL` \| `resume` \| `branch` \| `subagent`. |
| `spawn_event_id` | TEXT NULL | For `subagent`: the parent `tool_call` event that launched it. |
| `branch_point_event_id` | TEXT NULL | For pi `resume`/`branch` and Cursor copied-prefix sessions: the last inherited event on the live branch — the **highest-`seq` inherited placement**, not max-`ts` (multi-block events share timestamps and source ts ≠ transcript order). |
| `tip_event_id` | TEXT NULL | This session's final live leaf — the entry point for reconstruction and the live-branch root for `live`. |
| `title` | TEXT NULL | Human title when available (Claude `ai-title` final value), else NULL/derived. |
| `hidden_at` | TEXT NULL | Retrieval visibility marker. NULL means visible in default discovery/search commands; non-NULL means hidden unless the command explicitly includes hidden sessions. Raw evidence is not deleted. |
| `hidden_reason` | TEXT NULL | Human reason for hiding a session from default retrieval. |

Visibility is manual and reversible (`sessdb hide`, `sessdb unhide`). It is a
structured DB policy over sessions, not a prompt-text classifier and not raw-evidence
scrubbing. Because the DB is a rebuildable cache, these manual markers are lost
if the DB is deleted and rebuilt from raw evidence.

## ID scheme

All ids are `<source>:`-prefixed (globally unique across sources, self-describing). Ids must be **copy-invariant**: an event copied between files keeps the same `event_id`, so copies dedup to one `events` row.

| | `session_id` | `event_id` |
|---|---|---|
| **Claude** | `claude:<sessionUuid>` | `claude:<uuid>` (already globally unique) |
| **Codex** | `codex:<sessionUuid>` | `codex:<sessionUuid>:<lineIndex>` (file is append-only, never copied across files) |
| **Cursor** | `cursor:<composerId>` | Timestamped: `cursor:<escapedBubbleId>:<epochMs>:<kind>`; untimed legacy: `cursor:<escapedComposerId>:<escapedBubbleId>:untimed:<kind>` |
| **pi** | `pi:<sessionUuid>` | `pi:<8hex>:<ts>` (+ block discriminator below) |

Cursor `<kind>` is `message`, `call`, or `result`. Timestamped IDs are
copy-invariant because copied bubbles retain bubble identity and authored time.
Untimed historical bubbles deliberately use a session scope and are never marked
inherited. Components are percent-escaped before joining.

**Why pi uses `<8hex>:<ts>`, not a lineage-root scope:** pi's 8-hex id is unique only within a lineage, *but* resume copies records **verbatim — same id and same timestamp**. So `(8hex, ts)` is copy-invariant and collision-*resistant* without resolving the lineage root (which a child file can't know — its `parentSession` names only the *immediate* parent). This avoids any global pre-scan: every pi file is ingestable in isolation. (Not collision-*proof* — see the copy-consistency check below.)

**pi multi-block records** (one assistant `message` record → a `message` event + N `tool_call` events) share the record's `8hex`+`ts`, so add a block discriminator: the `message` event is `pi:<8hex>:<ts>`; each `tool_call` event is `pi:<8hex>:<ts>:<toolCall.id>` (the `toolCall.id` is itself copied verbatim). `toolResult` events come from their own record → `pi:<resultId>:<ts>`.

## Ingest contract

- **Dedup / idempotency**: upsert `events` on `event_id` (copy-invariant → copies collapse to one row). Re-ingesting a file is a no-op.
- **Placement**: each file contributes one `session_events` row per event it contains (including inherited copies — this *is* the occurrence record). PK `(session_id, event_id)` makes re-ingest idempotent.
- **Origin (no tie-break needed)**: an event's `inherited` flag is decided
  **locally** — for pi and timestamped Cursor bubbles,
  `inherited = (event.ts < session.created_at)`; untimed Cursor and all
  Claude/Codex events are authored. Cursor enforces that emitted inherited
  bubbles are a contiguous prefix. The origin is the single session where
  `inherited=0`; set `events.origin_session_id` from it. If only inherited copies
  exist so far (ancestor not yet synced), `origin_session_id` stays NULL and
  fills in later — content is never lost. Order-independent.
- **Origin invariant (has teeth)**: at most **one** `inherited=0` placement per event (so `origin_session_id` is 0-or-1, NULL until the origin is ingested). If ingest would create a *second* non-inherited placement — e.g. a copied event whose `ts` exactly ties the child's `created_at` and gets misread as authored — **do not overwrite** the origin (the upsert keeps the first non-null `origin_session_id`).
- **Copy-consistency check**: for ordinary append-only sources, an `events`
  upsert that hits an existing `event_id` whose actor/type/text differs signals
  an id collision or a non-verbatim copy — **flag, don't merge**, keep the first
  row, and skip just that placement. Two distinct non-null
  `origin_session_id` values are always a hard conflict, even if their content
  matches.
- **Cursor revision authority**: a validated Cursor head carries the total rank
  `(revision, snapshotDigest)`. `cursor_session_heads` records the greatest rank
  accepted for each canonical session in the same transaction as its session,
  events, placements, derived indexes, and `ingest_state`; equal/lower ranks
  cannot mutate canonical state. Within a newer accepted head, authored evidence
  replaces provisional inherited content and later content from the same author
  replaces its mutable `text`/`refs`/`raw` fields. An inherited copy never
  overwrites authored evidence, but its placement is retained. Conflicting
  inherited-only variants converge by canonical full-row digest until the
  author arrives. Timestamp, actor, type, intrinsic result pairing, and distinct
  authored origins remain hard collisions. Stable Cursor event IDs deliberately
  do not include a payload or revision hash.
- **No content-hashing for identity** (two identical `ls` calls are distinct). Content hashing belongs to the derivations cache, not here.
- **Refresh-on-read (delta ingest)**: the internal `ingest_state` table (NOT part of the canonical model — bookkeeping, rebuildable) records each raw file's `(mtime, size)` at last parse. Cursor additionally uses root-scoped `cursor_archive_heads` rows: a no-follow metadata signature per hashed session directory, its validated selected head, and the last selection deliberately handled by ingest. An unchanged directory opens no revision JSON; a changed directory revalidates only its own chain. Selection and handled state remain separate so out-of-order predecessors, corruption fallback, and failed writes retry correctly. Both tables are disposable cache state. `refresh()` runs in front of every CLI read; full `ingest` remains the first-build / disaster-recovery pass.
- **Re-parse is authoritative for placements**: re-ingesting a file *replaces* that session's `session_events` rows (delete-then-insert) — `seq`/`live`/`parent` are whole-session properties, so a grown file (e.g. a rollback appended later) must be able to flip earlier placements. `events` rows are never deleted: upstream file deletion never deletes from the archive.
- **FTS**: `events_fts` is an external-content FTS5 index kept current by triggers on `events` — incremental by construction; `rebuild_fts` exists only as repair.

## Per-event normalization

### actor / type

| canonical | Claude | pi | Codex | Cursor |
|---|---|---|---|---|
| user / message | `user` record, string content | `message` role `user` | user input item | bubble `type=1` text |
| assistant / message | `text` block | `message` role `assistant`, `text` block | assistant text item | bubble `type=2` nonblank text |
| assistant / tool_call | `tool_use` block | `toolCall` block | function/tool call item | bubble `toolFormerData` |
| tool / tool_result | `tool_result` (user record) | `message` role `toolResult` | tool output item | terminal/result-bearing `toolFormerData` |

Tool pairing (`tool_call` ↔ `tool_result`) by tool id: Claude
`tool_use.id`==`tool_result.tool_use_id`; pi
`toolCall.id`==`toolResult.toolCallId`; Codex `call_id`; Cursor call and result
are two components of the same bubble and share its structured
`toolFormerData.toolCallId`. This pairing is recorded on
`events.tool_call_event_id` — **not** via `parent_event_id` (which is transcript
order; for parallel tool calls the paired call and the transcript predecessor are
different events).

### text
- `message` → text content. `tool_call` → compact rendering of salient args (the `bash` command, the file path) so commands are FTS-findable; full args in `raw`. `tool_result` → result text (untruncated; index layer chunks).

### refs
- `files` — Claude `toolUseResult.filePath`/`structuredPatch`; pi
  `read|write|edit` arg `path`; Codex `apply_patch` envelope; exact allowlisted
  Cursor tool-name/argument fields. (Shell-side mutations are invisible
  everywhere — known gap.)
- `commands` — the command string from `bash`/`shell`/`exec` calls and exact
  allowlisted Cursor terminal tools.

### Reasoning exclusion
Reasoning is **not** emitted. For ordinary sources it remains in original raw
logs; Cursor thought and summary text is removed at the safe-projection firewall
and never enters the archive. Dropped nodes/bubbles are skipped, and the next
emitted event's `parent_event_id`/`seq` point at the nearest emitted predecessor.
The same mechanism absorbs pi's non-message tree nodes (`model_change`,
`thinking_level_change`, `compaction`).

## Linearization — how `seq`, `parent_event_id`, `live` are computed

The adapter reconstructs each session's transcript at **ingest time** (reads don't parent-walk). `parent_event_id`/`seq` are the **normalized transcript predecessor/order** of *emitted* events — not the raw source parent (kept in `raw`). This avoids overloading one pointer with raw ancestry and display order, and sidesteps the parallel-tool/parent-walk pitfall in `formats/claude.md`.

Per source (mechanics in the format docs):
- **Claude** — group blocks by `requestId`, order within a response, pair tool_use↔tool_result by id, drop thinking. Forks: rollback losers → `live=0`; parallel tool calls are real siblings, both `live=1`.
- **pi** — walk `parentId`, skipping control/reasoning nodes. Forks are rollback-only (loser subtree `live=0`). Inherited prefix is copied with its parent links intact.
- **Codex** — **synthesize** the tree (no source parents): maintain a stack of live turns; each clean human prompt, plus native inter-agent messages, starts a turn parented to the current live tip; `thread_rolled_back{num_turns:N}` pops N *live* turns (not the last N physical lines); subsequent turns parent to the new stack top; popped turns stay as `live=0` side branches. `turn_id`/source line are preserved in `raw` for audit.
- **Cursor** — use the projection's complete logical bubble order, skip hidden
  thought/summary bubbles, expand each visible bubble into message/call/result
  components, and link emitted events linearly. Settled snapshots represent the
  current live transcript, so every emitted placement is live. Timestamped
  copied bubbles before `created_at` form the inherited prefix.

**Dangling predecessor → root:** if a placement's computed predecessor isn't an emitted event in this session — e.g. a pi child that inherited only a post-compaction *suffix*, whose first inherited event's source parent was summarized away — set `parent_event_id=NULL` (a root) rather than pointing at a missing event. (General rule; protects against any dropped/uncopied parent.)

`live` = on the path from a root to `sessions.tip_event_id`. Computed per session, so a pi event can be `live=1` in a child and `live=0` in a parent that later rolled back past it — exactly the case a single event-level flag couldn't represent.

## Sessions: lineage & sub-agents

- **pi resume/branch** → new `sessions` row; `parent_session_id` from the `parentSession` **filename uuid** (immediate parent; that's all that's needed); `relation=resume|branch`; `branch_point_event_id` = last inherited event. Inherited events get `session_events` rows here (`inherited=1`); they dedup to the shared `events` row owned by the ancestor.
- **Codex resume** → same file/same id → no new row; events continue.
- **Sub-agents (all sources)** → own `sessions` row, `relation=subagent`, `parent_session_id`=spawner, `spawn_event_id`=launching `tool_call`:
  - Claude `<sessionId>/subagents/agent-<hash>.jsonl` ↔ parent `Task` tool_use. Sub-agent records carry the *parent's* sessionId, so mint `session_id = claude:<parentUuid>:sub:<hash>` from the `agent-<hash>` filename. **Ignore the inline `isSidechain:true` copies in the parent file** — the same records (same uuid) live in the sub-agent file, their canonical home; placing the inline copies would wrongly graft them into the parent transcript. (Event-id dedup is the backstop if both are ingested anyway.)
  - Codex separate rollout ↔ `forked_from_id` / `spawn_agent` `agent_id`.
  - Cursor composer ↔ `subagentInfo.parentComposerId`; `spawn_event_id` is set
    only when the safe projection uniquely resolves the parent bubble by
    structured tool-call and child-composer IDs.
  - pi `<session>/<runId>/run-<i>/session.jsonl` ↔ `subagent` toolResult `details.runId` (+ task index `i`).
- A lineage-spanning "logical conversation" is **not** materialized — navigate `parent_session_id` (the forest already encodes it).

## Worked example

**Claude.** Records `u1` user → `a0` thinking → `a1` text → `a2` tool_use Read(foo.py) → `t1` tool_result → `a3` text. Thinking `a0` dropped; linearization makes `a1`'s predecessor `u1`.

`events`:

| event_id | origin_session_id | actor | type | text | refs |
|---|---|---|---|---|---|
| claude:u1 | claude:S | user | message | "fix the bug" | |
| claude:a1 | claude:S | assistant | message | "I'll look" | |
| claude:a2 | claude:S | assistant | tool_call | "Read foo.py" | files:[foo.py] |
| claude:t1 | claude:S | tool | tool_result | "<contents>" | |
| claude:a3 | claude:S | assistant | message | "fixed" | |

`session_events` (single session, all live, all authored):

| session_id | event_id | seq | parent_event_id | live | inherited |
|---|---|---|---|---|---|
| claude:S | claude:u1 | 0 | — | 1 | 0 |
| claude:S | claude:a1 | 1 | claude:u1 | 1 | 0 |
| claude:S | claude:a2 | 2 | claude:a1 | 1 | 0 |
| claude:S | claude:t1 | 3 | claude:a2 | 1 | 0 |
| claude:S | claude:a3 | 4 | claude:t1 | 1 | 0 |

**pi resume (the case the split exists for).** Event `E` authored in session `A`, inherited by resumed child `B`. One `events` row (`origin_session_id=pi:A`), two placements:

| session_id | event_id | seq | live | inherited |
|---|---|---|---|---|
| pi:A | pi:e9:tsE | 5 | 1 | 0 |
| pi:B | pi:e9:tsE | 5 | 1 | 1 |

If `A` later rolls back past `E`, only `A`'s row flips to `live=0`; `B`'s stays `live=1`.

## Derived layers (out of scope, for orientation)
- **FTS5** over `events.text`; **sqlite-vec** over chunked `events.text` (later); **grep** runs over the raw pool directly.
- **`file_refs`** (built) — `events.refs.files` unrolled to `(event_id, file, basename)`, indexed on `basename`, so `touched` is an indexed lookup instead of a `json_array_length` scan over every event. Keyed on `event_id` (content); placement/visibility come from the `session_events` join. A rebuildable derivation: populated on first event insert and one-time-backfilled for older caches. `basename` is normalized by `codebrain.paths` (the same code the query side uses) so an indexed basename lookup never misses a real match.
- The intent-browsing commands are index-served at corpus scale: `ix_ev_actor_type_ts` on `events(actor, type, ts)` backs `userlog`/`recent`; a one-time bounded `ANALYZE` (`sqlite_stat1`) keeps the planner from mis-choosing it.
- User-message provenance is a rebuildable evidence overlay, not canonical event
  truth. Cursor derives it only from exact source flags/IDs and canonical
  relation/authored/sequence fields; contradictory structured evidence becomes
  `unknown`, and message text never participates. See `formats/cursor.md`.

## Intentionally excluded
- **Reasoning / thinking** — not normalized; for Cursor it is also excluded from
  the safe raw archive. This makes "redact thinking" the default, not a filter.
- **Per-message metrics** (pi tokens + cost) — single-source, not central to retrieval; recoverable from `raw`.
